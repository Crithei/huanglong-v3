# 开发指南

适合准备改代码或改内容的组员。只改文案的话，先看「数据」一节就够了。

## 运行方式

所有脚本都是普通的 `<script>`，不是 ES 模块，也没有构建步骤。这样双击 `index.html`（`file://`）也能运行，发单文件版时也不需要服务器。代价是文件之间不能 `import`，只能通过一个全局对象 `window.HL` 共享。

加载顺序写在 `index.html` 底部，必须遵守依赖关系：

```
core/hl.js            HL 命名空间、esc / icon / safeUrl 等工具、HL.act()
data/*.js             往 HL.data 里填内容
core/model.js         HL.idx 索引、距离与时间换算、路线计算
core/state.js         HL.S 游客状态、HL.store 存取与撤销
core/router.js        HL.setPage / HL.renderAll
ui/*.js               插图、列表行、色带、弹层、提示
features/*.js         详情弹层、数字人导游
pages/*.js            四个页面
main.js               事件分发与首次渲染（必须最后）
```

新增 JS 或 CSS 文件后要加进 `index.html`，`tools/check.py` 会提示有没有漏加。

## 核心约定

### 页面模块

每个页面登记一个对象：

```js
HL.pages.services = {
  render() { /* 把整页 HTML 写进 #p-services */ },
  onShow() { /* 可选：切到这一页时调用 */ },
};
```

`HL.renderAll()` 依次调用四页的 `render()`；状态变化后需要刷新时调用它。游览页的地图要读容器尺寸，所以它的 `render()` 只在游览页可见时执行，并通过 `onShow` 在切过去时补画。

### 动作（点击事件）

页面不单独绑定点击事件。可点的元素写 `data-act="名称"`，再在任意模块里登记：

```js
HL.act('want', el => {
  const id = el.dataset.id;
  // …
});
```

`main.js` 统一监听点击，找到最近的 `[data-act]` 后调用对应函数，元素上的其他 `data-*` 用来传参。

- 动作名只用小写字母、数字和连字符，全局唯一。重复登记会在控制台报警，`check.py` 也会报错。
- 写了 `data-act` 却没有登记，`check.py` 会报错；运行时点击也会在控制台提示。

现有动作：

| 动作 | 所在文件 | 作用 |
| --- | --- | --- |
| `tab` | core/router.js | 切换底部页面（`data-page`） |
| `close` | ui/sheet.js | 关闭弹层 |
| `station` / `product` / `card` | features/details.js | 打开景点、商品、内容卡片详情（`data-id`） |
| `card-go` | features/details.js | 详情里的内部跳转按钮 |
| `wish` / `want` | features/details.js | 收藏景点 / 想要文创 |
| `go-tour` | pages/tour.js | 进入游览页并切到某个面板（`data-panel`） |
| `select` / `step` | pages/tour.js | 选中某站 / 上一站、下一站 |
| `panel` / `fac-filter` / `fac` | pages/tour.js | 切换面板 / 设施筛选 / 定位设施 |
| `visit` / `toggle-stop` / `restore-route` | pages/tour.js | 打卡 / 移出或加回路线 / 恢复全部 |
| `guide` / `ask` / `guide-act` | features/guide.js | 打开导游 / 提问 / 回答里的按钮 |
| `reset` | pages/services.js | 清空本机记录 |

### 状态

`HL.S` 是游客在本机的全部状态，存在 `localStorage` 的 `huanglong.v3.1` 键下（地址带 `?demo` 时用 `huanglong.v3.demo`，给汇报页用）：

| 字段 | 含义 |
| --- | --- |
| `page` | 当前底部页面 |
| `current` | 游览页当前站 |
| `panel` | 游览面板：`station` / `fac` / `route` |
| `fac` / `facFocus` | 设施筛选类型 / 地图上高亮的设施 |
| `mapMode` | 地图底图：`vector` 地图 / `satellite` 卫星 / `schematic` 示意图 |
| `plan` | 游线规划条件：`hours` 可用小时 / `pace` 节奏 / `mode` 偏好 / `cable` 是否坐索道上行 |
| `water` | 水滴四章：`active` 当前章 / `chapters` 各章进度 / `badgeAt` 四章集齐时间 |
| `off` | 只路过、不停留的站（地图上为空心点） |
| `visited` | 已打卡的站 |
| `wish` / `want` | 想去的景点 / 想要的文创 |
| `seen` | 已点亮的生灵徽章 |

修改状态的固定写法：

```js
const before = HL.store.snapshot();   // 需要撤销时先存快照
HL.S.visited.push(id);
HL.store.save();
HL.renderAll();
HL.toast('已收下印章', { label: '撤销', fn: () => HL.store.restore(before) });
```

`HL.S` 始终是同一个对象，可以在模块顶部 `const S = HL.S`。新增字段时，要在 `state.js` 的 `defaults()` 和 `sanitize()` 里同时添加。如果改了已有字段的含义，把 `KEY` 末尾的版本号加一，这样旧草稿会被丢弃，不会按错误的结构读进来。

### 拼 HTML

页面用模板字符串拼 HTML。**所有来自数据或用户输入的文字都要经过 `HL.esc()`**。网址先过 `HL.safeUrl()`，它只放行完整的 http(s) 地址。图标写 `HL.icon('名称')`，名称对应 `index.html` 顶部 sprite 里的 `#i-名称`。

可复用的片段：

- `HL.row({ act, id, icon, title, sub, end, chev })`：列表行，服务、设施、收藏都用它；
- `HL.strata(interactive)`：沿途色带；
- `HL.media(station, cls)`：景点图，有照片用照片，没有就画示意图；
- `HL.openSheet({ title, body, foot, cls, tag })`、`HL.closeSheet()`：底部弹层；
- `HL.toast(文字, { label, fn })`：轻提示，可以带一个操作按钮。

### 样式

- 颜色、字体只用 `src/styles/base.css` 里 `:root` 的令牌（`--ink`、`--deep`、`--pool`、`--gold` 等）。确实需要新颜色时，先加令牌，再引用。
- 每个页面的样式写在自己的文件里，选择器以页面特有的类名开头，避免影响别的页面。
- 可点区域至少 44×44px；保留 `:focus-visible` 焦点框；动画要在 `prefers-reduced-motion` 下关闭。
- 需要检查 320、390、430px 竖屏和桌面画幅。数字人按钮不能挡住底部导航、弹层和主要按钮。

## 数据

`src/data/` 下每个文件都是「一段注释 + `HL.data.名称 = <JSON>;`」。等号右边必须是**合法 JSON**：

- 只用双引号；
- 最后一项后面不加逗号；
- JSON 部分不能写注释（说明写在本文档里）。

`tools/check.py` 会解析这些文件并逐项检查。写错时它会指出文件和大致行号。

### 景点 `stations.js`

数组顺序就是游线顺序，第一站是起点，最后一站是终点。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 文字 | 唯一编号，英文小写加连字符，定下来后不要改（打卡记录用它） |
| `name` | 文字 | 景点名 |
| `category` | 文字 | 类型，如「彩池」「瀑布钙华」「人文自然」，会影响示意图画法 |
| `area` | 文字 | 所在区段 |
| `minutes` | 整数 | 建议停留分钟数，同时决定色带宽度 |
| `effort` | 1–3 | 体力消耗；「轻松」节奏和「低负担」偏好会优先让它路过 |
| `tint` | `#rrggbb` | 代表色，用于色带、地图点、印章 |
| `loc` | `[经度, 纬度]` | GCJ-02 坐标 |
| `tagline` | 文字 | 一句话看点 |
| `summary` | 文字 | 简短介绍（规划偏好也按它判断类型） |
| `viewing` / `photoTip` / `tip` | 文字 | 看什么 / 怎么拍 / 留意 |
| `photo` | 对象或 `null` | `{ "src": "assets/photos/xxx.jpg", "credit": "作者，授权，来源", "page": "原图页面网址" }`；`page` 有值时署名会变成链接；没有照片时自动画示意图。只用能确认地点、协议允许的图（如 Wikimedia Commons 的 CC BY / CC BY-SA / CC0），并把作者、协议写全 |
| `facts` | `[[名称, 数值], …]` | 关键数据小标签，如 `["海拔", "3576 米"]`。**只写有可靠出处的数字**（目前取自景区官网），出处同时写进 `sources` |

以下字段 2026-11-02 从 v1（`data/scenic.js`）并入，`check.py` 会检查：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `aliases` | 文字列表 | 别名（不含正式名），给搜索、数字人、攻略导入匹配用 |
| `collection` | `pond` / `waterfall` / `landform` / `culture` | 大类：彩池 / 瀑布 / 地貌 / 人文 |
| `rank` | 整数 | 优先级，越大越值得停下细看；游线规划和导游减站都用它 |
| `intro` | 文字 | 详情弹层的正文 |
| `highlights` | 文字列表 | 三条左右的看点 |
| `tradeoff` / `expectation` | 文字 | 怎么取舍 / 现场预期（显示在「留意」里） |
| `story` | 文字列表 | 「背后的故事」段落，默认收起 |
| `sources` | `[{ title, url, note }]` | 资料来源，`url` 必须是 http(s) |
| `checkedAt` | 文字 | 内容核对日期 |

### 游线规划 `features/planner.js`

`HL.plan(条件, 已打卡)` 只计算不改状态，返回细看哪些站（`kept`）、路过哪些站（`deferred`）、估算用时、里程、缓冲和一句理由。条件存在 `S.plan`，应用建议统一调用 `HL.applyPlan()`（写入 `S.off`，可撤销）。黄龙是一条主栈道，14 站都会经过，所以「放不下」的站是改成路过，不是删掉。

规则改自 v1 的 `buildPlan`，数字都是原型估算，写在文件顶部注释里；以后有实测步行和停留数据时，只改 `planner.js` 顶部的常数。数字人要改路线时也调用这两个函数，不要另写一套。

### 水滴四章 `features/water.js`

内嵌在底栏「互动」页最上面的播放器（`pages/play.js` 建页面骨架，`HL.waterMount()` 装入，之后只刷新、不重建），不再有二级页面。顶部四个章节标签，每章显示标题、三个关键词、一句「怎么玩」，长的科普说明收在「科普说明」里。四章：水流（穿过山林，三消开路）、溶解（走进岩层，拖 CO₂ 气团）、出露（遇见天空，旋转裂隙岩层）、沉积（长成彩池，带水滴生成三片池）。

| 部分 | 位置 | 说明 |
| --- | --- | --- |
| 状态机 | `vendor/huanglong-water/follow-state.js` | v1 原样搬来，`window.HuanglongJournal`：解锁、互动规则、计时、奖励、存档校验 |
| 三维场景 | `vendor/huanglong-water/water-scene.js` | v1 原样搬来（含 Three.js，约 575 KB），播放器第一次滚进屏幕时才加载；滚出屏幕或切到别的页就暂停 |
| 界面 | `src/features/water.js`、`src/styles/water.css` | 内嵌播放器、棋盘、拖放、镜头按钮；规则沿用 v1，文案压成关键词（原文见 v1 提交 28797c5） |
| 进度 | `S.water` | `active` 当前章，`chapters` 各章进度，`badgeAt` 四章集齐时间；读档时交给状态机校验 |

**解锁规则：** 章节和景点的对应写在状态机的 `CHAPTERS`（水流：金沙铺地 / 迎宾池；溶解：洗身洞观景台；出露：飞瀑流辉 / 莲台飞瀑；沉积：五彩池 / 争艳彩池 / 盆景池）。任一关联景点「到站打卡」（`S.visited`）就解锁，顺序不限；未解锁可以预览模型。玩游戏、看详情都不会产生打卡。撤回打卡后，那一章再读档时进度会被清掉（与 v1 一致）。

**入口：** 首页「随行互动」卡片（停留示意下方，模型截图加标题）；底栏「互动」页；本站攻略里关联站的提示条；打卡后若解锁新章节，提示里有「去看看」；服务页「一滴水的旅程」（`go: "water"`）。`HL.goTour('water')` 和数字人的 `openPanel(water)` 都转到互动页。代码里打开某章：`HL.openWater('flow')`。

**没有三维时：** 场景脚本加载失败、浏览器不支持 WebGL、或在 `build-single.py` 打出的单文件里（不含 575 KB 的场景），播放器显示二维示意，棋盘和按钮照常可以通关。

**改玩法、模型或解锁景点：** 不要改 `vendor/` 里的文件，按 `vendor/huanglong-water/README.md` 在 v1 改好、测好再复制过来。只改文案、样式、按钮布局的话改 `water.js` / `water.css`。

### 彩池演化实验室 `features/lab.js`

内嵌在互动页一滴水下面（`HL.labMount()`）。页面上默认只露出池群画面和「开始演化 / 展开实验室」两个按钮，条件滑杆、预设、选池子、观察卡、贴纸进度都在点「展开实验室」后出现；从别处打开（`HL.openLab()`）时自动展开。一片四池相连的池群（上游池 → 左侧池 / 右侧池 → 下游池），改变来水、溶解钙供给、CO₂ 逸散条件、光照四个条件，看蓄水、溢流、池沿沉积怎样连续变化。可以起点对照（拖动画面分界线）、点池子看剖面、留下最多 6 张观察卡。

| 部分 | 位置 | 说明 |
| --- | --- | --- |
| 模型 | `vendor/huanglong-pool/pool-lab-state.js` | v1 原样搬来，`window.HuanglongPoolModel`：定性模型、三类发现、文字解释、存档校验 |
| 画面 | `vendor/huanglong-pool/pool-lab-scene.js` | v1 原样搬来，`window.HuanglongPoolScene`：Canvas 池群与 SVG 剖面 |
| 界面 | `src/features/lab.js`、`src/styles/lab.css` | 和一滴水一样铺满屏宽；规则沿用 v1，控件说明压成关键词 |
| 进度 | `S.lab` | 池群状态、对照起点、观察卡、选中池、速度、已记录发现、贴纸时间；读档时用模型校验，恢复后一律暂停 |

**贴纸：** 在五彩池、金沙铺地、争艳彩池、迎宾池任一处到站打卡后，「留下这次观察」时记录水路连起来、看见水退下去、池沿留下薄层三类发现，集齐得「池群观察者」。未打卡也能完整探索（预习模式），只是发现不计入。

**和数字人的联动：** 「留下这次观察」旁边和每张观察卡都有「问问华屿」——把当时的条件和池子状态写成问题，换到钙华研学的华屿来答；数字人每次回答都会读到实验室状态（`HL.labSituation()`）；数字人可以提议 `openLab(preset)`，按钮点开后按预设调好条件（`HL.openLab('low')`，预设见 `HL.LAB_PRESETS`）。

**入口：** 首页「随行互动」卡片；本站攻略里四个彩池类景点（`stickers.pool.poiIds`）的提示条（`HL.labHint()`）；第一次在这类景点打卡、又没解锁新水滴章节时，提示里有「去实验室」；底栏「互动」页（一滴水下面）和「池群观察者」贴纸详情；服务页「彩池演化实验室」（`go: "lab"`）；数字人按钮。这些入口都切到互动页并滚到实验室（`HL.openLab()`）；一滴水同理（`HL.openWater(章节)`）。进度变化时互动页标题旁的计数跟着更新。v1 的「写进手账」等手账搬来后再接。

**待机动画：** 没在演化时池群上有一道慢慢扫过的水光，「开始演化」轻轻发光；一滴水里能玩的章节标签有呼吸的小圆点，气团、水滴、目标光环和解锁按钮有轻微动效。都放在 `prefers-reduced-motion: no-preference` 里，开了减少动态效果就不动。

**暂停规则（沿用 v1）：** 默认暂停；切到别的页、切到后台、画面滚出视野、开启「减少动态效果」时暂停，回来不自动播放、不追赶时间。减少动态效果下只能用「推演一段」。

### 徽章与印章 `data/badges.js`

- 景点印章：`stations.js` 的 `stamp` 指向 `assets/stamps/` 里的印章，没打卡时变灰。迎宾池、飞瀑流辉、金沙铺地、盆景池、争艳彩池、五彩池是 v1 手绘章；其余 8 站由 `tools/make-stamps.py` 生成，框、名牌和点缀照抄 v1，只换中间的场景，改场景后重新运行它即可。`stamp` 为空的站才退回代码画的圆章。
- 主题徽章：按 `main` 里这六枚主章计数——「山水初见」任意两枚、「山水同行」任意三枚、「细节发现者」任意两枚加一枚实验贴纸。规则和文字沿用 v1 `data/passport.js`。
- 实验贴纸：目前只有彩池实验室的「池群观察者」。v1 另有一池水色、薄水金纹、时间薄片三张贴纸，属于已被实验室取代的旧实验，没有搬。
- 显示在互动页「徽章与贴纸」；判断函数 `HL.badgeStatus()` 在 `pages/play.js`。
- 生灵徽章 `species`：十种动物，图在 `assets/species/`，逻辑在 `features/species.js`。每种绑定 `stations`（一到两站）和一条观察线索 `clue`。规则：在 `stations` 任一站打卡后，互动页显出剪影，站点面板出现「这一段的生灵」；在那一站点「找到了」就点亮，记在 `S.seen`。线索写的是栈道上看得到的生境（灌丛、松萝、箭竹、冷杉林、天空），不要求真的遇见动物，和打卡一样由游客自己勾选。撤回打卡时，只靠这一站点亮的徽章一起收回。数字人导游只做「了解更多」：徽章详情里的按钮直接问生物多样性导游（`qiyu`），不参与点亮；`keywords` 给 `HL.speciesIn()` 用，云端不通时内置回答遇到物种名就用 `description` 作答。

### 内容卡片 `cards.js`

```
quick      首页三个快捷入口
services   服务页：[{ title: 组名, items: [卡片…] }, …]
products   首页文创商店；有 variants 的商品用实物效果图
mine       服务页「我的记录」里的旅行记录
```

卡片字段沿用第二版 `showcase-data.json`，可以直接对照：

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一编号 |
| `kind` | 卡片类别（service / video / game / demo / avatar / audio / product / journal …），目前只用于说明 |
| `title` / `subtitle` / `body` | 标题 / 短说明（用「 · 」分隔，显示成顿号）/ 详情正文（换行分段；「标签：内容」显示为键值） |
| `icon` | 图标名，需在 sprite 里存在（文创商品不需要） |
| `go` | 内部去向，见下表；不跳转就留空 |
| `url` | 外部作品网址，必须是完整的 http/https 地址；没有就留空 |
| `cta` | 主按钮文字 |
| `author` | 作品署名，显示在详情底部 |
| `variants` | 只用于文创商品：`[{ label: 款式名, img: 图片路径 }]`，第一张当封面，详情里点缩略图换大图；不填则用 `art.js` 的示意插画 |
| `fit` | 只用于文创商品：封面是透明底的图（如徽章）时填 `contain`，完整显示不裁切；默认 `cover` |
| `featured` | 仅服务页：`true` 时作为顶部醒目入口（目前是高原反应服务） |
| `lead` | 仅醒目入口：入口上的一句提示 |
| `hint` | 没有 `url` 和 `go` 时，详情底部显示的说明 |

`go` 可以填的值：

| 值 | 效果 |
| --- | --- |
| `home` / `play` / `services` | 切到对应页面（`play` 是互动页） |
| `records` | 打开服务页并滚到「我的记录」 |
| `tour` | 进入游览页「本站攻略」 |
| `facilities` | 进入游览页「沿途设施」 |
| `medical` | 在地图上定位离当前站最近的医疗点 |
| `guide` | 打开数字人导游对话 |

详情按钮的规则（`features/details.js` 的 `openCard`）：

1. 填了 `url`：主按钮在新标签页打开作品，按钮文字用 `cta`；
2. 填了 `go`：显示内部跳转按钮（同时有 `url` 时变成次按钮）；
3. 两者都没有：显示 `hint` 和「知道了」。

新增 `go` 去向时，要在 `details.js` 的 `GO` 和 `tools/check.py` 的 `GO` 两处都加上。

### 在「探索与互动」里加一个入口

复制该组任意一张卡片，粘到 `items` 末尾，然后：

- 改 `id`，例如 `service-star`；
- 改 `title`、`subtitle`、`body`、`cta`；
- 从 sprite 里挑一个 `icon`（或先新增一个图标）；

### 新增一个图标

在 `index.html` 顶部的 `<defs>` 里，照现有写法加一个 24×24 的线条 `symbol`，例如 `<symbol id="i-star" viewBox="0 0 24 24">…</symbol>`，然后用 `HL.icon('star')` 或在卡片里写 `"icon": "star"`。

### 数字人导游（WorkBuddy 云端问答）

2026-11-02 起，导游对话默认走云端问答，流程沿用「黄龙数字人网页端交接包」：

1. 按当前角色的板块（`public` 华汐 / `karst` 华屿 / `orchid` 兰蕙 / `biodiv` 朗嘎）在云端知识库检索 6 条片段；
2. 组装规则（只依据片段回答、照抄数字、标注 `[n]` 引用、禁答清单）+ 「游客此刻」（当前站、细看 / 路过、打卡、规划条件、一滴水进度）+ 「页面命令」说明；
3. 流式生成，边生成边显示；回答末尾的 `<<cmd {"name":…,"args":{…}}>>` 按白名单校验后变成按钮。

| 文件 | 内容 |
| --- | --- |
| `src/data/guide.js` | 云端配置（公开只读密钥、模型）、通用回答规范、四位角色的人设 / 欢迎语 / 常用问题 / 服务范围 / 转接话术。**改人设、改话术只改这里** |
| `src/features/guide-cloud.js` | 云端回答来源：检索、组装提示词、流式生成、命令白名单、依据折叠、转接按钮、失败退回 |
| `src/features/guide.js` | 对话弹层、角色切换条、内置规则回答（`HL.guide.rules`）、按钮动作 |
| `vendor/workbuddy/` | 云端 SDK（第一次提问时加载） |
| `assets/guide/` | 四位角色头像（来自交接包） |

**页面命令（模型只能提议，游客点了才生效）：**

| 命令 | 变成 | 点了以后 |
| --- | --- | --- |
| `showStation(id)` | 「在游览中看某站」 | `HL.selectStation` |
| `findFacility(type)` | 「在地图上看某设施」（离当前站最近的） | `HL.focusFacility` |
| `planRoute(hours, pace, mode, cable)` | 对话里的规划对比卡 +「按这个安排调整路线 / 先不改」 | 写入 `S.plan` 并 `HL.applyPlan()`，可撤销 |
| `openWater(chapter)` | 「打开一滴水某章」 | `HL.openWater` |
| `openPanel(panel)` | 「打开某面板」 | `HL.goTour` |

模型的回答里点名其他角色（如「请切换到【华屿】」）时，会多一个「换华屿来答」按钮。打卡、清空记录等不开放给模型。新增命令：在 `guide-cloud.js` 的 `toActs()` 加一个分支、在 `commandGuide()` 写说明、在 `guide.js` 的 `guideAct()` 处理按钮。

**退回内置回答：** 云端连不上、来源校验不通过（`auth_*`）、额度不足（`quota_*`）、或知识库一条都没检索到时，改用 `HL.guide.rules`，回答上方注明原因。内置规则仍能找设施、减站、处理高反提示。

**域名白名单：** 云端按来源域名校验。本机预览 `http://localhost:4191` 已实测可用（交接文档说 localhost / 127.0.0.1 都已放通）；线上 `huanglong.nyxal.site` 不在白名单里，走同源代理：worker 生成的 `config.local.js` 给出 `HL.config.cloudProxy`，页面改请求 `/cloud/.cloud/…`，`worker/index.js` 把 Origin 换成登记域名再转给云端。代理只放行 `kb_search` 和大模型对话两个接口，只接受从我们网站发起的请求。平台正式放行后删掉 worker 里这一段即可，页面会自动改回直连。双击打开 `index.html`（`file://`）和单文件版也会被拒，同样退回内置回答。

**换成自建后端时：** 只需重写 `guide-cloud.js` 里调用云端的两处（`kb_search` 和 `chat.completions.create`），或整体换一个 `HL.guide.provider`；回答对象格式见 `guide.js` 顶部注释。不要把大模型 API Key 写进前端，放到 Worker 的 Secret 里由后端转发。

### 地图（腾讯地图 JS API GL）

游览页的地图对外只有两个函数：`HL.renderMap()`（按当前状态重画）和 `HL.ping(loc)`（让用户看到某个坐标）。面板、导游、详情都只调用这两个函数，不关心底下是哪种地图。

| 文件 | 职责 |
| --- | --- |
| `src/pages/tour-map.js` | 调度：决定显示腾讯地图还是示意图；内置 SVG 示意图；「地图 / 卫星 / 示意」切换（动作 `map-mode`） |
| `src/pages/tour-map-tencent.js` | 腾讯地图：读 Key、加载 JSAPI、创建地图、画景点 / 游线 / 设施 / 文字，`HL.realMap` |
| `src/config.example.js` | 本机配置模板（进仓库，Key 留空） |
| `src/config.local.js` | 本机配置（**不进仓库**），由地图模块按需加载 |

**本机启用地图：**

1. 到 [腾讯位置服务控制台](https://lbs.qq.com/dev/console/key/manage) 申请一个网页专用的 Key（启用「JavaScript API GL」），域名白名单填 `127.0.0.1`、`localhost`；
2. 复制 `src/config.example.js` 为 `src/config.local.js`，把 Key 填进 `HL.config.tmapKey`；
3. 用 `python -m http.server 4191 --bind 127.0.0.1` 打开（双击 `index.html` 时浏览器来源为空，域名白名单通常不放行）。

没有 Key、断网、超时 12 秒、浏览器不支持 WebGL 时，`HL.realMap.status` 变成 `failed`，自动显示示意图，其他功能不受影响。`build-single.py` 打出的单文件不带 Key，打开就是示意图。

**画在地图上的东西：** 景点圆点（颜色取 `tint`，当前站有深色外圈、移出路线的站为空心、打过卡的有中心点）；按站序连起来的金色虚线（只是示意，**不是**实际栈道走向）；「沿途设施」面板下的设施方块（颜色与列表一致）；当前站名与选中设施名。点击景点 → `HL.selectStation`，点击设施 → `HL.focusFacility`，和点列表完全一样。

**写地图代码时：** 只用腾讯官方文档里有的类和参数（`TMap.Map`、`MultiMarker`、`MultiPolyline`、`MultiLabel` 等），坐标 `[经度, 纬度]` 转 `new TMap.LatLng(纬度, 经度)`；数据已是 GCJ-02，不要再转换。

**Key 在哪里：** 本机开发时 Key 写在 `config.local.js`，浏览器能看到，只用于本机。线上用腾讯官方的「代理服务转发」：页面只拿到代理地址 `HL.config.tmapProxy`，在加载 JSAPI 前设置 `window._TMapSecurityConfig`，JSAPI 不带 Key 加载，需要 Key 的请求发到 `/_TMapService/…`，由 `worker/index.js` 补上 Secret 里的 Key 再转给腾讯。线上页面的源码和网络请求里都没有 Key。景区内的步行时间不要用腾讯路线规划的结果（按普通路网估算，不含栈道爬升），继续用 `stations.js` 的停留时间和站序。

## 汇报页 `present/index.html`

翻页式汇报：左边用 iframe 嵌入 `../index.html?demo`，右边是讲解。和网站同源，所以能直接调用左侧的 `HL`：

- 右边翻页 → 调用这一页的 `apply(H)`，把左边调成对应界面；「在左边试试」按钮调用 `tries`；
- 左边操作 → 每 0.4 秒用各页的 `match(状态)` 判断左边当前界面，当前页对不上就翻到第一页对得上的讲解。封面、工程、下一步标了 `passive`：停在上面时左边是首页不算错，但不会被自动翻到。

地址带 `?demo` 时网站用单独的演示存档 `huanglong.v3.demo`（`state.js` 的 `KEY`），不碰游客自己的进度；「重置演示」把演示存档恢复成预设（已在四处打卡）。新增或修改一页：改 `present/index.html` 里的 `SLIDES`。

## 部署（Cloudflare Workers）

线上地址：<https://huanglong.nyxal.site/>（备用：<https://huanglong-v3.itsmephrynx.workers.dev/>）。

| 文件 | 作用 |
| --- | --- |
| `wrangler.jsonc` | Worker 名 `huanglong-v3`，静态文件目录为仓库根目录，自定义域名 `huanglong.nyxal.site` |
| `.assetsignore` | 不上传的文件：文档、工具、`dist/`、`.git`、部署配置、本机 Key 文件。线上只有 `index.html`、`src/`、`assets/` |
| `worker/index.js` | 静态文件之外的请求：① `/_TMapService/…` 腾讯地图 Key 代理，用 Secret `TMAP_JS_KEY` 补 Key，只接受来源（Origin / Referer）是本站的请求，其他一律 403；只转发地图本身需要的统计、Key 校验、海外控制三条，官方示例里的 `/service`（WebService）**故意不转发**，因为伪造 Referer 的脚本能绕过来源检查；② `/src/config.local.js` 只返回代理地址，不含 Key |

**发布新版本：推到 GitHub 的 `main` 就会自动部署**（2026-11-02 起，Cloudflare Workers Builds 已连接仓库 `Crithei/huanglong-v3`）。每次推送 Cloudflare 会：

1. 拉取代码，运行构建命令 `python3 tools/check.py`，检查不通过就停止，不会上线；
2. 运行部署命令 `npx wrangler deploy`，按 `wrangler.jsonc` 和 `.assetsignore` 上传。

推送到其他分支只运行预览命令 `npx wrangler versions upload`：生成一个预览版本和链接，不替换正式站。构建记录在 Cloudflare 后台 Workers & Pages → `huanglong-v3` → Deployments / Builds 里看；构建设置在 Settings → Builds。

所以 **`main` 上的每个提交都会直接上线**。多人开发时各自开分支，通过 PR 合并到 `main`；建议在 GitHub 里给 `main` 打开分支保护，要求 PR 后才能合并。

部署后检查：首页能打开、游览页显示腾讯地图、`/README.md` 和 `/tools/check.py` 返回 404。

**手动部署**（紧急修复或排查构建问题时用，需要能登录这个 Cloudflare 账号）：

```bash
python tools/check.py
npx wrangler@4 deploy
```

手动部署的是本地文件，可能包含没提交的改动；下一次推送 `main` 时会被自动部署覆盖。

**更换地图 Key**：`npx wrangler@4 secret put TMAP_JS_KEY`，按提示粘贴新 Key（不要通过管道传入，会带上换行；Worker 已做去空白处理）。设置后立即生效，不用重新部署。换了域名时，要同时改 `wrangler.jsonc` 的 `routes` 和 `worker/index.js` 的 `ALLOWED_HOSTS`，否则地图请求会被 403。
